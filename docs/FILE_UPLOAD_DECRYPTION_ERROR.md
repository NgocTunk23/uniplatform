# File Upload Decryption Error - Fix Guide

## Problem

When uploading files to Google Drive, you may encounter this error:
```
❌ File Controller Upload Error: Error: Unsupported state or unable to authenticate data
```

This happens because the app cannot decrypt your stored Google Drive refresh token.

## Root Cause

The error "Unsupported state or unable to authenticate data" from AES-256-GCM decryption means the **authentication tag verification failed**, which indicates one of these scenarios:

1. **Encryption Key Changed**: The `DRIVE_TOKEN_ENCRYPTION_KEY` or `JWT_SECRET` environment variable was modified after the token was encrypted
2. **Corrupted Data**: The encrypted token in the database was modified or corrupted
3. **Wrong Algorithm**: The stored token was encrypted with a different algorithm/version

## Solutions

### Solution 1: Verify Current Environment Key (Quick Check)

Run the diagnostic script:
```bash
node scripts/diagnose-encryption.js "YOUR_ENCRYPTED_TOKEN_HERE"
```

This will:
- Check if `DRIVE_TOKEN_ENCRYPTION_KEY` is set
- Verify token format is correct (v1:iv:tag:ciphertext)
- Attempt decryption and report the error

### Solution 2: Reconnect Google Drive (Easiest Fix)

Simply disconnect and reconnect Google Drive from the app:

1. Go to **Drive Files** in the app
2. Click **Disconnect Google Drive**
3. Click **Connect Google Drive** and complete the OAuth flow
4. Try uploading again

This will store a fresh encrypted token using the current environment key.

### Solution 3: Re-encrypt Token Manually (Advanced)

If you have your refresh token saved elsewhere:

```bash
node scripts/diagnose-encryption.js --encrypt "YOUR_REFRESH_TOKEN_HERE"
```

This will output a new encrypted value ready for the database:
```
v1:base64url(iv):base64url(tag):base64url(ciphertext)
```

Then update your database:
```javascript
await prisma.user.update({
  where: { username: 'your_username' },
  data: { googleDriveRefreshToken: 'v1:...' }
});
```

### Solution 4: Check Environment Key Consistency

In production, ensure `DRIVE_TOKEN_ENCRYPTION_KEY` is:
- The same across all app instances (use same value in all .env files)
- Not changed after tokens are encrypted
- Set in Docker/Kubernetes secrets if using containers

## Technical Details

### Encryption Format

Google Drive refresh tokens are encrypted using:
- **Algorithm**: AES-256-GCM
- **IV**: 12-byte random initialization vector
- **Authentication Tag**: Automatically generated by cipher.getAuthTag()
- **Format**: `v1:base64url(iv):base64url(tag):base64url(ciphertext)`

### Key Derivation

```javascript
const key = crypto.createHash('sha256')
  .update(process.env.DRIVE_TOKEN_ENCRYPTION_KEY || process.env.JWT_SECRET)
  .digest();
```

### What Happens During Decryption

1. Parse token into [version, iv, tag, ciphertext] parts
2. Create decipher with AES-256-GCM algorithm
3. Set the authentication tag
4. Decrypt the ciphertext
5. **Final authentication check** ← This fails with "Unsupported state" if tag is wrong

## Recovery in Production

If multiple users are affected:

1. **Temporary Workaround**: Remove Google Drive file uploads (keep other features)
2. **Mass Re-encryption**: 
   - If you have a backup of the encryption key, verify it's being used
   - If key was lost, users must reconnect via OAuth
3. **Migration**: 
   - Export refresh tokens from backup using old key
   - Re-encrypt using new key
   - Update database in bulk

## Prevention

1. **Environment Management**:
   ```bash
   # Use the same key across all environments
   export DRIVE_TOKEN_ENCRYPTION_KEY="your-secret-key"
   ```

2. **Key Rotation** (if needed):
   - Maintain both old and new key during transition
   - Re-encrypt all tokens with new key
   - Update environment to use new key

3. **Monitoring**:
   - Log decryption errors (now includes helpful messages)
   - Alert on repeated failures
   - Track user-initiated reconnections

## Error Messages Reference

| Error | Cause | Solution |
|-------|-------|----------|
| "Unsupported state or unable to authenticate data" | Auth tag mismatch | See Solution 1-2 above |
| "Invalid encrypted secret format" | Token not in v1:...: format | Check database corruption, Solution 3 |
| "DRIVE_TOKEN_ENCRYPTION_KEY or JWT_SECRET not set" | Missing env var | Set in .env or Docker secrets |
| "Malformed ObjectID" | Database schema issue | Contact support |
